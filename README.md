# MYB

Личная библиотека и читалка TXT/PDF/Markdown (.md) для Android, iOS и macOS.

Markdown открывается с заголовками, списками, выделением, таблицами, кодом и
ссылками. Страницы разделяются между блоками, чтобы не разрывать таблицы и
блоки кода. Сохраняются цитаты и позиция чтения, как для TXT и PDF.

## Каталог книг из Go и SQLite

Запустите сервер из папки `backend`, где находится рабочая база `myb.db`:

```sh
cd backend
go run .
```

Если сервер уже запущен, остановите его через Ctrl+C и запустите снова после
изменения кода. По умолчанию сервер слушает порт 8080 на сетевых интерфейсах.
Для доступа только с этого компьютера: `BOOKS_LISTEN_ADDR=127.0.0.1:8080 go run .`.

В отдельном терминале из корня проекта запустите приложение:

```sh
flutter run -d macos
```

На macOS и в симуляторе iOS каталог загружается с `http://127.0.0.1:8080`,
в Android Emulator — с `http://10.0.2.2:8080`. Другой адрес можно передать
через `--dart-define=BOOKS_API_URL=https://your-server.example`.

Для физического телефона подключите Mac и телефон к одной Wi-Fi сети.
Узнайте локальный IP Mac в настройках сети и запустите, подставив свой адрес:

```sh
flutter run -d <device-id> --dart-define=BOOKS_API_URL=http://192.168.1.10:8080
```

Разрешите приложению доступ к локальной сети, а серверу — входящие соединения,
если система предложит. Проверьте `http://<IP-Mac>:8080/books` в браузере телефона.
Изменение `BOOKS_API_URL` требует повторного запуска Flutter, hot reload недостаточно.
Для опубликованного сервера используйте HTTPS.

Книги из `GET /books` появляются на главной и в поиске; каталог можно обновить
кнопкой со стрелкой. «Читать» скачивает файл из поля `link`, сохраняет его в
данных приложения и открывает встроенную читалку. PDF, TXT и Markdown доступны
повторно без интернета, позиция чтения сохраняется на устройстве.
Приложение поддерживает перенаправления ссылок и показывает ошибку, если файл
недоступен или вместо PDF пришла HTML-страница.

Последний загруженный каталог кэшируется. Если сервер недоступен и кэша ещё нет,
показывается встроенная подборка с соответствующим сообщением. Книги без ссылки
можно просмотреть, но скачать их из каталога нельзя.

## iOS

Требуются macOS, полный Xcode и SDK iOS. Минимальная версия iOS — 15.0.

```sh
flutter pub get
bash tool/release_ios.sh
```

Скрипт собирает `build/ios/archive/Runner.xcarchive` и упаковывает приложение
в `build/releases/ios/v1.0.3/MYB-iOS-1.0.3-unsigned.ipa` с `SHA256SUMS`.
Это сборка **без подписи**: для установки на iPhone или публикации требуется
подписать её сертификатом Apple и соответствующим provisioning profile.
Для повторной упаковки готового архива используйте `--skip-build`.

Для подписанной сборки откройте `ios/Runner.xcworkspace` в Xcode, выберите
Runner → Signing & Capabilities, задайте свою Team и доступный Bundle Identifier,
затем выполните `flutter build ipa --release`. Экспортированный подписанный
IPA появится в `build/ios/ipa/`.

Для установки на свой iPhone без подписки Developer Program войдите в
Xcode → Settings → Apple Accounts, выберите свою Personal Team в
Runner → Signing & Capabilities и подключите разблокированный iPhone к Mac.
Включена автоматическая подпись для всех конфигураций Runner; iOS Bundle ID —
`com.karinaandros.myb` (у macOS свой идентификатор). В Xcode выберите iPhone
в качестве устройства запуска и нажмите Run, либо выполните
`flutter run --release -d <iphone-id>`. При запросе на iPhone включите Developer
Mode и подтвердите доверие Mac. Для Personal Team основной путь — установка
из Xcode или Flutter на своё устройство, а не экспорт для App Store.

После настройки Team подписанный пакет для зарегистрированного iPhone можно
собрать командой `bash tool/release_ios.sh --signed`. Для уже собранного
приложения добавьте `--skip-build`. Файл
`build/releases/ios/v1.0.3/MYB-iOS-1.0.3-signed.ipa` содержит подпись Apple и
профиль устройства. Скрипт проверяет подпись, соответствие Bundle ID и срок
действия профиля. Первое открытие на iPhone может требовать подтверждения
профиля в «Настройки → Основные → VPN и управление устройством».
У Personal Team срок действия профиля ограничен; после его истечения
приложение необходимо подписать и установить повторно.

Проверка в симуляторе:

```sh
flutter build ios --simulator --debug
flutter run -d <simulator-id>
```

## macOS

Требуется macOS 12 или новее, Flutter с Dart 3.13.2+ и полный Xcode из App Store.
Command Line Tools отдельно от Xcode не позволяют собрать приложение macOS.

После установки Xcode откройте его и завершите первоначальную настройку. Затем:

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
flutter pub get
flutter run -d macos
```

В VS Code / IDE на его основе выберите профиль **MYB — macOS** в разделе
Run and Debug и нажмите F5. Он явно использует устройство `macos`.
Профиль **MYB — выбранное устройство** использует текущее устройство IDE.

Проект использует Swift Package Manager для macOS-плагинов.

Сборка приложения:

```sh
flutter build macos --release
```

Результат: `build/macos/Build/Products/Release/MYB.app`.

Окно сохраняет размер и положение; минимальная область содержимого — 960 × 640.

| Сочетание | Действие |
| --- | --- |
| ⌘O | Открыть TXT/PDF/MD в библиотеке |
| ⌘F | Поиск книги или автора в библиотеке |
| ⌘1…⌘5 | Разделы библиотеки |
| ⌘⇧R | Подобрать случайную книгу |
| ⌘D | Переключить тему |
| ⌘, | Настройки |
| ← / →, Page Up / Page Down | Страницы в читалке |
| Esc | Вернуться из читалки |

Команды библиотеки активны на основном экране. Импорт использует стандартный
диалог macOS и разрешение на чтение выбранного пользователем файла. Локальные
копии книг, цитаты и прогресс хранятся в данных приложения.

### Обновления приложения

Sparkle 2.10.1 встроен через Swift Package Manager. «Настройки → Проверить
обновления» открывает стандартное окно проверки,
скачивания и установки. Sparkle также предлагает включить периодическую
проверку. Перед перезапуском приложение сохраняет текущую страницу и
статистику чтения.

Настройки открываются шестерёнкой в шапке или через «MYB → Настройки…» (⌘,).
«Сбросить кэш» очищает кэш изображений, вычисленные цвета обложек и временные
загрузки PDF. Книги, цитаты, избранное, статистика, настройки темы и текущая
страница сохраняются; активные файлы импорта и шрифты также не удаляются.

Канал: `https://github.com/KarinaAndros/reader_flutter/releases/latest/download/appcast.xml`.
Пока первый релиз с этим файлом не опубликован, проверка сообщит об ошибке
загрузки канала. Приватный ключ подписи создан в Связке ключей этого Mac,
учётная запись `com.example.flutterApp.sparkle`; в приложении хранится только
публичный ключ. Архивы и сам appcast подписываются Ed25519; Sandbox включён.

Для следующей версии:

1. Увеличить **оба** номера в `pubspec.yaml`, например `1.0.4+5`.
2. Написать `releases/macos-1.0.4.md`.
3. Выполнить `bash tool/release_macos.sh` на этом Mac.
4. Опубликовать обычный GitHub Release `v1.0.4` с готовыми файлами из
   `build/releases/v1.0.4`: ZIP, `appcast.xml`, `SHA256SUMS`. Релиз должен
   стать Latest, а тег — указывать на соответствующий исходный код.

Для упаковки уже собранной версии: `bash tool/release_macos.sh --skip-build`.
Скрипт проверяет версию, ключ, подпись приложения, подписи архива и канала.
Подписи проверяются встроенным публичным ключом через CryptoKit, без чтения
приватного ключа. Для отдельной проверки готового пакета:

```sh
xcrun swift tool/verify_macos_release.swift \
  build/macos/Build/Products/Release/MYB.app/Contents/Info.plist \
  build/releases/v1.0.2/appcast.xml \
  build/releases/v1.0.2/MYB-macOS-1.0.2.zip
```

Не редактируйте подписанный XML вручную: изменение требует повторной подписи.
Храните резервную копию ключа безопасно вне репозитория: новые обновления
должны подписываться тем же ключом, которому доверяет установленное приложение.

Актуальный пакет готов в `build/releases/v1.0.2`. Для ручной публикации откройте
https://github.com/KarinaAndros/reader_flutter/releases/new, задайте тег
`v1.0.2`, название `MYB 1.0.2`, прикрепите `MYB-macOS-1.0.2.zip`,
`appcast.xml` и `SHA256SUMS`. Отметьте **Set as latest release** и опубликуйте
обычный релиз, без **This is a pre-release**. Описание можно взять из
`releases/macos-1.0.2.md`. Актуальные исходники следует отправить в репозиторий
перед созданием тега. ZIP загружается как есть, без распаковки и переименования.

После публикации откройте Настройки → Проверить обновления: для установленной
версии 1.0.1 (2) ожидается предложение обновиться до 1.0.2 (3).
Публикация и проверка онлайн-канала пока выполняются пользователем.

Инструкция GitHub: https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository.

## Проверки

```sh
flutter analyze
flutter test
```

Для нативных PDF-тестов можно задать `PDFIUM_PATH`. На Apple Silicon также
поддерживается библиотека из локального Flutter-кэша сборки, указанная в
`test/pdf_page_turn_test.dart`.
